# カードバトル オンライン版

対戦カードゲーム「カードバトル」のオンライン対戦版です。
別々のスマホ／PCから、ルームコードで同じ試合に入って対戦できます。
ローカルモード（CPU対戦・同じ端末で2人対戦・カード編集）もそのまま入っています。
**このフォルダは「無料サーバーへデプロイする直前」の状態です。デプロイ作業（アカウント作成・公開）はまだ行っていません。**

## 遊び方（ルール概要）

本体（Netlify公開中の単一HTML版）と完全に同じルールです。

- お互いHP30・手札4枚でスタート。自分のターン開始時に1枚ドロー（試合の先手の初ターンのみドローなし）。
- エネルギーは毎ターン全回復し、最大値が1ずつ増える（初期最大2→初ターン3、上限8）。カードはコスト分のエネルギーを払って出す。
- カードセットは、ルームを作ったホストが使っているもの（カード編集の内容を含む）を両者が使います。ホストが編集していなければ標準セット（16種・デッキ32枚）です。両者がまったく同じデッキで戦うので公平です。ゲスト側の編集内容は使われません。
- ホストから送られたカードセットは、サーバー側で検証・サニタイズしてから採用します（検証ルールは本体の編集データ取り込みと同じ：属性・名前・コスト・効果数値の範囲チェック、デッキ枚数0〜4枚など）。セットが不正で使えない場合は対戦を止めず、標準セットにフォールバックしてホストにその旨を通知します。
- 攻撃は相手のシールドから先に削れる。「貫通」はシールドを無視してHPを直接削る。
- 毒は、毒を受けた側のターン開始時に2ダメージ（貫通）。ポイズンダガーは毒2回分を付与（重ねがけは最大値まで）。
- 山札が尽きたら捨て札をシャッフルして再利用。それもなければ引くたびに1ダメージ。
- 手札の上限は8枚。あふれたカードは捨て札になる。
- 相手のHPを0にしたら勝ち。降参もできます（オンライン版では自分のターンでなくても降参できます）。

### オンライン対戦の流れ

1. どちらかが「オンライン対戦」→「ルームを作る」。4文字のルームコードが表示されます。このとき、ルームを作った人（ホスト）の現在のカードセット（カード編集の内容を含む）がサーバーへ送られ、そのルームの対戦に採用されます。参加待ち画面と対戦画面には、ホストの編集セットで対戦中か標準セットで対戦中かが表示されます。
2. そのコードを相手に送り、相手が「コードで参加する」から入力すると対戦開始。
3. あとは本体と同じ対戦画面です。自分の手札からカードを出し、「ターン終了」で交代。
4. 決着後は「もう一戦」でそのまま再戦できます。

```
cardbattle-online/
├─ server.js        … HTTP配信＋WebSocketサーバー（審判役）
├─ game.js          … ゲームロジック（本体ルールのサーバー移植・各プレイヤー向け表示生成）
├─ public/
│  └─ index.html    … クライアント（本体の単一HTMLをそのまま土台に、オンライン画面を追加）

│  └─ TEST_RESULTS.md … テスト結果の記録
├─ package.json

```

### 仕組みのポイント
- **状態はサーバーが一元管理（審判方式）**します。クライアントは「カードを出す」「ターン終了」といった操作だけを送り、結果の計算はすべてサーバー側です。不正な操作（相手ターン中のカード使用など）はサーバーがエラーで弾きます。
- **手札などの秘匿情報は本人のクライアントにだけ送ります。** 相手には HP・シールド・毒・エネルギー・手札の「枚数」・山札枚数だけが届くので、相手の手札を覗くことはできません（`game.js` の `viewFor()` で送信データを組み立てています）。
- **再接続**：入室時に発行されるプレイヤーIDをブラウザ（localStorage）に保存し、回線が切れても同じルームに同じ席で復帰できます（ロビーの「前の対戦に戻る」から）。
- **カードセットの扱い**：ルーム作成時にホストのカードセットがサーバーへ送られ、`game.js` の `resolveCardSet()` が本体と同じ方針で検証・サニタイズします（カード名24文字まで、コスト0〜8、攻撃などの効果数値の上限、デッキ枚数0〜4枚、カード種数は最大64種）。範囲外の数値は範囲内に丸められ、名前のないカードなどは除外されます。使えるカードが残らない・デッキが0枚になるなどセット全体が不正な場合は、標準セットにフォールバックし、ホストに通知します。ホストが編集していない（標準セットと同一内容の）場合は「標準カードセット」として扱われます。再戦（もう一戦）でも同じセットを引き継ぎます。

## ローカルでの動かし方

前提：Node.js 18以上

```bash
cd cardbattle-online
npm install   # 初回のみ（ws を取得）
npm start     # サーバー起動（http://localhost:3000）
```

ブラウザを2つ（またはスマホとPCなど）で `http://localhost:3000` を開き、
1人目が「ルームを作る」→表示された4文字コードを、2人目が入力して「参加する」を押せば開始です。
（同じPCで試す場合は、別ウィンドウやシークレットウィンドウを使うと楽です）

自動テスト：
```bash
npm test           # 単体＋統合テスト（72件）
npm run test:multi # 複数ルーム同時進行（8件）
```

## Render 無料枠へのデプロイ手順（ここから先はユーザーの作業）

> アカウント作成とデプロイは、ご自身で行ってください。以下は手順書です。

1. https://render.com でアカウントを作成（GitHubアカウントでサインアップが楽です）。
2. このフォルダ（cardbattle-online）を、ご自身の GitHub リポジトリにアップロード（push）します。
3. Render のダッシュボードで **New → Web Service** を選び、そのリポジトリを接続します。
4. 設定値：
   - **Runtime**: Node
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: Free
5. **Create Web Service** を押すとデプロイが始まります。数分で `https://（サービス名）.onrender.com` のようなURLが発行されます。
6. そのURLをふたりのスマホで開けば、どこからでも対戦できます（WebSocket は自動で wss 接続になります）。

※ Render の無料枠を使わず、自分のPCで動かし続ける方法でも遊べますが、その場合はPCの電源とネット接続が必要です。

## 注意点（大事）

- **無料枠は約15分アクセスがないとスリープ**します。次に開いたときの初回表示に30〜60秒ほどかかることがあります。
- **サーバーが再起動するとルームは全部消えます**（状態はメモリ上だけに保持しているため）。スリープからの復帰＝再起動なので、対戦中にスリープすると試合はリセットされます。遊ぶ直前にページを開いて「起こして」おくのがおすすめです。
- ルームコードは4文字の簡易なものです。知らない人が偶然入ってくる可能性がゼロではないので、コードは遊ぶ相手だけに共有してください（本格的な認証はありません）。
- **複数ルーム同時対応**：サーバーは複数のルームを同時並行で処理できます。状態が混ざらないことを自動テスト（`npm run test:multi`）で確認済みです。ゲームの状態は軽量（1ルームあたり数KB程度）なので、友達同士の規模なら無料枠の性能で十分です。安全のためルーム数の上限は50に設定してあり、30分間誰も接続していないルームは自動で片付けます。
- データの永続化（戦績保存など）は未実装です。
- クライアントは本体と同じ単一HTMLファイル構成のため、CSS/JSは別ファイルではなくHTML内に含まれています。

## 本体との差分（オンライン化に伴う変更点）

- カード編集はオンライン対戦にも反映されます（ホストの編集済みセットを両者が使う方式）。本体のローカル対戦では各プレイヤーではなく共通の編集セットを両者が使う点は同じです。オンラインではゲスト側の編集内容は使われません。
- 降参は、本体では手番プレイヤーが対象でしたが、オンライン版では自分の意思でいつでも降参できます（降参した側の負け、という意味は同じ）。
- CPUの「つよい」（HP+5・手札+1）はローカルCPU戦専用のため、オンラインにはありません。
- それ以外のルール（効果の解決順、毒・山札切れ・手札上限、両者同時HP0の場合は手番側の負け）は本体と同一に実装し、自動テストで検証しています。

## デプロイ後にやりたいこと（任意）

- Render の有料プランや常時起動のVPSに移すと、スリープとルーム消滅が解消します。
- 状態をデータベース（Render の PostgreSQL 等）に保存すれば、再起動しても試合を継続できます（要改修）。
